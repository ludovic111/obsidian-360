1080P STUDY AND INDEPENDENT BOOT — OCTOBER 1, 2026
Result: desktop kept at 1280 × 720 at 60 Hz. The switch to 1920 × 1080 was requested on the XRandR output None-1; response "cannot find mode 1920x1080". No persistent resolution change was applied.
Analysis of the available code: xenos_load reads D1GRPH_X_END/Y_END and builds fixed_mode; the DRM connector exposes this mode inherited from the loader. The libxenon mode list examined contains no 1920 × 1080. A real addition would require HDMI/ANA/HANA video programming and adapting the driver, with hardware validation. Changing only the framebuffer size does not guarantee a 1080p output.
Sources: https://github.com/Free60Project/linux-kernel-xbox360 and https://github.com/Free60Project/libxenon/blob/master/libxenon/drivers/xenos/xenos_videomodes.h
Boot: BadUpdate acts after the authenticated Xbox boot and does not persist after power-off. The internal disk is already dedicated to Linux; erasing the NAND does not constitute a Linux installation and would remove the current boot path. No new secure boot bypass was discovered in this study.
The known route to launch XeLL/Linux independently of the dashboard is a compatible RGH hardware modification, followed by a boot image adapted to the console. The exact motherboard and a hardware recovery method must be identified before any firmware write. ABadAvatar can further automate the triggering but retains a dependency on the Xbox system.
Sources: https://github.com/grimdoomer/Xbox360BadUpdate; https://github.com/FreeMyXe/FreeMyXe; https://free60.org/Hacks/Reset_Glitch_Hack/; https://github.com/15432/RGH3
The present Linux kernel exposes neither /proc/mtd nor /dev/mtd. No complete NAND backup was therefore obtained in this session. The earlier backups are disk regions, not a NAND backup. No NAND flashing or erasure performed.
